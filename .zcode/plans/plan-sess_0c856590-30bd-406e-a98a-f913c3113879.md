# 历史数据加速收敛（重启状态恢复 + 前馈偏差校正）

## 目标

1. **重启不再重收敛**：HA 重启/集成重载后，恢复上次收敛状态（已写入设定值、原始默认设定值、步进节奏），跳过 feedforward 重算，从中断处继续。
2. **前馈第一笔更准**：用 recorder 近 24h 历史计算「参考温度 − 空调自感温度」的**稳态中值偏差**，替代 feedforward 目前用的瞬时偏差；同时用最近读数**预热中值滤波窗口**，消除冷启动单样本裸奔。
3. 全部优雅降级：recorder 未启用 / 历史不足 / 恢复数据缺失时，行为退回现状，不引入新依赖与硬性故障路径。

**决策记录**（重启开关语义问题未获回答，按推荐项执行，可在审查时否决）：保持现状——重启后总是自动恢复跟随（夜间空调自动停止后若 HA 重启，早晨开空调无需手动再开）。本次不改动 enable 语义，只恢复收敛状态。

## 改动范围（7 个文件 + 新增 1 个）

### `custom_components/follow_me_climate/const.py`
新增常量（非用户选项）：`BIAS_WINDOW = 24h`、`BIAS_MIN_SAMPLES = 20`（样本对不足则退回瞬时偏差）、`BIAS_MAX_INSTANT_GAP = 5.0°C`（学习值与瞬时值差距过大视为异常，弃用）、`BIAS_PAIR_WINDOW = 300s`（配对时参考读数与空调状态的最大时间距离）。

### `custom_components/follow_me_climate/controller.py`（纯逻辑，全部可单测）
- 新增模块级纯函数 `median_bias(pairs) -> float | None`：对 (ref, ac_temp) 样本对取中值，样本 < `BIAS_MIN_SAMPLES` 返回 None。
- `__init__` 新增：`wall_now_fn`（默认 `time.time`，可注入）、`learned_bias`、`last_action_wall`、`_pending_restore`。
- `_record()` 同步记录壁钟时间 `last_action_wall`（与 rate gate 的 `last_action_ts` 一一对应）。
- feedforward（步骤 4）改为偏差择优：`learned_bias` 存在且与瞬时偏差差距 ≤ `BIAS_MAX_INSTANT_GAP` 时用学习值（且**无需 ac_temp 也可前馈**——学习值独立成立）；否则退回瞬时 `ref - ac_temp`（现状）。
- 新增三个方法：`prime_readings(values)`（填预热样本进 `_readings`）、`stage_restore(...)`（实体层恢复数据暂存）、`apply_staged_restore()`（在 `enable()` 之后调用：恢复 `_written_sp`（钳位到 min/max）、`_default_sp`（非法则保留 enable 快照）、`last_action_ts = max(0, now − 壁钟差)`，使 rate gate 续接而非重启后立刻抢写；同时恢复 `last_action` 文本）。
- 新增 `default_sp` 只读属性供传感器暴露。

### `custom_components/follow_me_climate/sensor.py`
- `FollowMeStatusSensor` 混入 `RestoreEntity`：`async_added_to_hass` 里 `async_get_last_state()`，从属性提取 `applied_setpoint` / `default_setpoint` / `last_action_time` / `last_action` → `controller.stage_restore(...)`。恢复的暂存数据在 `__init__.py` 的 setup 尾部（enable 之后）应用，规避 `enable()` 清空状态的时序。
- status 属性新增 `default_setpoint`、`last_action_time`（诊断可见，也是恢复数据源）。

### `custom_components/follow_me_climate/history.py`（新文件，HA 层）
- `_prime_from_history(hass, controller, merged)`：guard `"recorder" in hass.config.components` + 全程 try/except + debug 日志，executor 执行：
  - `recorder.history.get_last_state_changes(hass, 3, ref_entity)` → 取新鲜（age < sensor_timeout）的数值 → `controller.prime_readings(...)`；
  - `recorder.history.get_significant_states(hass, now−24h, [climate, ref], significant_changes_only=False)` → 双指针按时间最近配对（空调状态须为 cool/heat 且带数值 `current_temperature`，时间距 ≤ `BIAS_PAIR_WINDOW`）→ `median_bias(...)` → `controller.learned_bias`。
- 实现时对照 HA 源码核实 `get_significant_states` 签名（2025.4–2026.8 稳定，低风险）。

### `custom_components/follow_me_climate/__init__.py`
setup 尾部改为：`enable()` → `apply_staged_restore()` → `await _prime_from_history(...)` → `_tick()`。平台先于该序列完成 setup（现有顺序已保证），传感器恢复数据就绪。

### `custom_components/follow_me_climate/manifest.json`
- `version` → `0.4.0`；`after_dependencies` 增加 `"recorder"`（软依赖，仅排序用，不加硬 dependencies，recorder 被禁用的实例不受影响）。

### `tests/test_controller.py`
沿用现有 FakeAdapter/假时钟/裸 asyncio 模式新增用例：`median_bias` 样本不足/中值正确；学习偏差参与前馈（含无 ac_temp 场景）；学习值与瞬时值差距超限退回瞬时；恢复 `_written_sp` 后首 tick 跳过 feedforward；恢复壁钟时间后 rate gate 推迟重启后首次写；恢复 `_default_sp` 后 disable 写回真实默认值；`prime_readings` 参与中值；`_record` 写壁钟时间。

### `README.md`
更新前馈描述（L13 一带）、安全机制表；新增小节「历史数据加速收敛」说明重启恢复、稳态偏差校正、降级路径。无新用户选项，translations 不动。

## 风险与取舍

- **重启总是自动恢复跟随**是保留的现状（未答问题按推荐项），如需改为严格恢复开关状态请否决本条。
- **恢复数据依赖 RestoreState 落盘**（周期性+关机时保存）：硬崩溃最坏情况退回现状（feedforward 重算），无回归。
- **学习偏差的季节漂移**由 24h 窗口约束；配对不按压缩机启停细分（中值本身抗离群），刻意不做更激进的房间增益学习（过冲风险与 evidence-paced 设计哲学冲突）。
- **HA 层代码无本地测试覆盖**（仓库测试套件零 HA 依赖，属既有约束），用防御式编程 + 实机验证兜底。
- 恢复 `_default_sp` 顺带修复现存缺陷：重启后 disable/sensor-lost 将恢复用户真实默认值，而非“重启时刻的已收敛值”。
