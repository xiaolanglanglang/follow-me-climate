# Follow-Me Climate 兼容 Home Assistant 2026.8 + 对齐最新写法

## 目标

修复集成在 HA 2026.8 下无法加载的导入错误，并把经验证确属「旧写法」的 API 迁到 2026.8 的规范写法。所有结论均已对真实安装的 homeassistant 2026.8.3 逐符号验证。

## 改动范围（6 个文件）

**1. `custom_components/follow_me_climate/__init__.py`（必修，当前 2026.8 下 ImportError）**
- 删除 `from homeassistant.components.climate.const import ATTR_TEMPERATURE`（该常量已从 climate.const 移除）。
- `ATTR_TEMPERATURE` 改从 `homeassistant.const` 导入（并入现有第 20 行导入，规范位置 const.py:456）。
- `ATTR_CURRENT_TEMPERATURE`、`SERVICE_SET_TEMPERATURE`、`DOMAIN` 改从包级 `homeassistant.components.climate` 导入（官方公开 re-export，climate.const 瘦身方向的长期稳定路径；值完全相同，零行为差异）。

**2. `custom_components/follow_me_climate/sensor.py`**
- 导入并使用枚举：`_attr_state_class = "measurement"` → `SensorStateClass.MEASUREMENT`（两处），`_attr_device_class = "temperature"` → `SensorDeviceClass.TEMPERATURE`。
- `AddEntitiesCallback` → `AddConfigEntryEntitiesCallback`（导入 + `async_setup_entry` 注解；后者是 2026.8 官方 EntityPlatformModule 协议使用的类型）。

**3. `custom_components/follow_me_climate/number.py`、`4. switch.py`**
- 同样的 `AddConfigEntryEntitiesCallback` 类型对齐（仅注解）。

**5. `custom_components/follow_me_climate/manifest.json`**
- `version` 0.1.0 → 0.1.1。

**6. `hacs.json`**
- 增加 `"homeassistant": "<最低版本>"` 字段，数值由实现期实测决定：装 HA 2025.4.4 于 /tmp venv 跑模块导入冒烟测试，通过则声明 `2025.4`；若缺符号（如 `AddConfigEntryEntitiesCallback`）则逐级上调实测版本，全部失败则不加此字段并在交付说明中注明。

**明确不改的部分（已验证为 2026.8 当前规范写法，非遗留代码）**：`DeviceInfo` 从 `device_registry` 导入（2026.8 中 `helpers/device_info` 模块不存在，`device_registry.py:116` 即规范位置）；平台三位置参数 `async_setup_entry` 签名（2026.8 源码 `entity_platform.py:462` 仍按此调用）；经典 voluptuous config flow / OptionsFlow 用法；`hass.data`、`async_forward_entry_setups` 等均未弃用。

## 关键步骤（遵循全局 worktree 规则）

1. 确认当前不在 worktree 中 → `git worktree add .worktrees/ha-2026-8-compat -b fix/ha-2026.8-compat`，并在该分支给 `.gitignore` 增加 `.worktrees/`。
2. 在 worktree 中完成上述 6 处编辑。
3. 验证门槛（全部通过才合并）：
   - 在 /tmp 的 2026.8.3 venv 中装 pytest，跑现有单测（controller 为 HA-free 纯逻辑，验证无回归，顺带覆盖 Python 3.14 运行时）。
   - 模块导入冒烟测试：7 个模块全量真实导入 + DeprecationWarning 升级为 error（仅过滤 aiohttp 的无关警告）。
   - 2025.4.4 floor venv 同样的冒烟测试 → 定 hacs.json 数值。
4. `git add -A && git commit`；回主仓库确认可快进后 `git merge --ff-only fix/ha-2026.8-compat`。
5. 清理：`cd` 回主仓库绝对路径 → `git worktree remove` → `git branch -d`。

## 风险与取舍

- climate 包级导入 vs 保留 climate.const：两者 2026.8 均可用，选包级是押注长期方向（const.py 正在瘦身），代价为零。
- `AddConfigEntryEntitiesCallback` 为纯注解替换（运行时鸭子类型无差异）；若 floor 实测缺该符号，回退该项为 `AddEntitiesCallback` 并上调/放弃 hacs.json 声明。
- 枚举化与导入迁移均为等值替换，无行为变化；验证为导入级 + 单测级，未起完整 HA 实例做端到端（config flow UI 未动，风险极低）。
