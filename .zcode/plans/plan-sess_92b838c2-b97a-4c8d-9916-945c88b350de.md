# 修复：Options 流程每次都强制重选空调和传感器

## 根因

`custom_components/follow_me_climate/config_flow.py` 的 `_build_schema()` 中，所有数值/开关参数都通过 `default(key, fallback)` 预填当前值，唯独 `CONF_CLIMATE_ENTITY` 和 `CONF_SENSOR_ENTITY` 两个 `vol.Required(...)` 字段（第 74-79 行）没有任何预填值。它们又是必填，所以每次打开 options 表单这两个实体选择器都是空的，必须重选才能提交。

## 改动（仅 1 个文件，2 个字段）

给这两个字段加 HA core 官方惯用的 `suggested_value` 预填：

```python
vol.Required(
    CONF_CLIMATE_ENTITY,
    description={"suggested_value": defaults.get(CONF_CLIMATE_ENTITY)},
): EntitySelector(EntitySelectorConfig(domain="climate")),
vol.Required(
    CONF_SENSOR_ENTITY,
    description={"suggested_value": defaults.get(CONF_SENSOR_ENTITY)},
): EntitySelector(EntitySelectorConfig(device_class="temperature")),
```

**为什么用 `suggested_value` 而不是 `default`**：首次配置流程中 `defaults` 为空，若写 `default=None`，voluptuous 会在缺 key 时直接以 None 通过校验（显式 default 绕过 required 检查），可能创建实体为 None 的坏条目。`suggested_value` 只让前端预填，服务端校验不变——首次流程不选仍报必填错误，options 流程预填当前实体、不动即可直接提交。

## 不需要改的部分

- 翻译文件：字段没增减，`en.json` / `zh-Hans.json` 原样适用。
- `__init__.py`：options 本来就保存全量字段，`merged = {**data, **options}` 逻辑已兼容。
- 无数据迁移。
