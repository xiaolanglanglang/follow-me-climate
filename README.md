# Follow-Me Climate（随身感恒温）

[Home Assistant](https://www.home-assistant.io/) 自定义集成：**以参考温度传感器（人所在位置）为准，闭环微调空调的设定温度**，解决空调自带传感器不准、不稳导致"人呆的地方过热/过冷"的问题。

名字致敬美的遥控器的 "Follow me/随感" 功能——人在哪，温度就以哪为准。

## 为什么需要它

变频空调靠自己的内机传感器做闭环：传感器误判室温（冷气下沉、安装位置偏高等），压缩机就会过早降频，人所在的位置始终达不到目标温度。

本集成**不信任空调自带传感器**，把外部参考传感器作为唯一可信源，用慢速闭环逐步微调空调设定值：

- 启动时用「参考温度 − 空调自感温度」的偏移做一次**前馈定位**（冷热模式同公式：`设定值 = 目标 − (参考 − 空调自感)`）；
- 之后每周期检查误差，超出死区就朝正确方向微调一步；
- 步长小、周期长、死区宽，压缩机平滑升降频，不会频繁启停。

```
ref = 中位数滤波(参考传感器)                  # 近 3 次采样抗毛刺
err = 参考温度 - 目标温度                     # 制冷语义；制热自动反号
|err| <= 死区      -> 不动
err > 死区 (制冷)  -> 设定值 -= 步长
err < -死区 (制冷) -> 设定值 += 步长
设定值始终钳位在 [下限, 上限]
```

## 功率动量门控（可选）

配置一个空调回路上的功率传感器（如带计量的智能插座）后，控制环从"盲步进"变成"看证据步进"：功率明显上升说明上一次下发已经在把房间拉向目标，就先暂缓下一步，等参考温度追上来——减少纯积分环因热惯性造成的过冲和来回摆动。

功率证据本身有滞后（变频压缩机升频需要时间，插座还有上报聚合延迟），所以算法刻意**不在下发后 3 分钟内判定功率**；这同时意味着功率启用时的实际最小步进间隔为 `max(调节间隔, 3 分钟)`。判定与安全网：

- **上升判定**：滤波功率较下发时刻的基线上升 ≥ max(30%, 30 W) → 暂缓步进；
- **释放**：功率回落到上升幅度的一半以下（滞回），或误差回到死区，或持续暂缓超过 **15 分钟**（超时后照常步进，并把当前功率重置为新基线，杜绝永久卡死）；
- **失效回退**：功率传感器不可用/超过 5 分钟没更新 → 门控立即失效，完全回退纯温度闭环；
- 功率只做"暂缓"，永远不取代参考温度环；试运行（dry-run）模式下门控不参与，功率仅展示。

状态传感器的属性 `power_w`（滤波功率）、`power_baseline_w`（基线）、`power_gate`（`off`/`unavailable`/`waiting`/`holding`/`open`）可直接观察门控行为。

## 安全机制

| 机制 | 行为 |
|---|---|
| 设定值钳位 | 默认 16–30°C，可配 |
| 人工接管保护 | 检测到遥控器/面板改了设定值 → 暂停（默认 30 分钟），到期后以人的设定值为新基线继续 |
| 传感器失联 | 超时（默认 10 分钟）→ 停止调整并恢复启用时的默认设定值，恢复后重新前馈定位 |
| 模式守卫 | 仅在制冷/制热模式动作，关机/送风/除湿不碰 |
| 空调关机联动 | 空调从制冷/制热被关掉时，总开关自动关闭并恢复默认设定值（可在选项里关掉此联动；空调重新开机不会自动恢复跟随） |
| 功率门控失效回退 | 功率传感器不可用/超时（5 分钟）→ 动量门控立即失效，回退纯温度闭环 |
| 功率动量超时 | 持续暂缓超过 15 分钟 → 恢复步进并重置功率基线，防止卡死 |
| Dry-run | 只计算不下发，用于试运行观察（功率门控不参与） |
| 关闭/卸载恢复 | 总开关关闭或卸载集成时，恢复启用时的默认设定值 |

## 安装

HACS → 前端仓库（自定义仓库）→ 添加 `https://github.com/xiaolanglanglang/follow-me-climate`，类别选**集成**，然后搜索 Follow-Me Climate 安装，重启 HA。

## 配置

设置 → 设备与服务 → 添加集成 → Follow-Me Climate：

| 参数 | 默认 | 说明 |
|---|---|---|
| 空调（climate 实体） | - | 任意 climate 实体（midea_ac_lan、小米、红外方案均可） |
| 参考温度传感器 | - | 人所在位置的温湿度/温度传感器 |
| 功率传感器（可选） | 不配置 | 空调回路上的功率（W）实体（如带计量的智能插座）；配置后启用功率动量门控 |
| 目标温度 | 26°C | 人所在位置想要达到的温度 |
| 调节步长 | 取空调自身步长 | 默认读取空调的 `target_temp_step`（未暴露则 0.5°C）；手动调过滑块后以你的值为准（0.5–2.0） |
| 调节间隔 | 4 分钟 | 两次微调最小间隔（1–15） |
| 死区 | ±0.5°C | 死区内不动作（0.1–1.5） |
| 空调设定值下限/上限 | 16 / 30°C | 钳位边界 |
| 传感器失联超时 | 10 分钟 | 超时判定失联并恢复默认 |
| 人工接管暂停 | 30 分钟 | 检测到手动改设定值后的暂停时长 |
| 前馈初始偏移 | 开 | 启动时按偏差一次性定位 |
| 试运行模式 | 关 | 只计算不下发 |
| 空调关闭时自动停用 | 开 | 空调关机时总开关自动关闭并恢复默认设定值 |

## 生成的实体

| 实体 | 说明 |
|---|---|
| `switch.<名称>` | 总开关（关闭时恢复默认设定值） |
| `number.<名称>_target_temperature` | 目标温度，运行时可调（滑块） |
| `number.<名称>_step` | 调节步长，运行时可调（滑块） |
| `sensor.<名称>_status` | 状态：`idle` / `adjusting` / `manual_pause` / `sensor_lost` / `inactive`（属性里有 detail、参考温度、已下发设定值、最近动作、`power_w`/`power_baseline_w`/`power_gate`） |
| `sensor.<名称>_offset` | 已施加偏移（当前下发设定值 − 目标温度） |
| `sensor.<名称>_reference` | 滤波后的参考温度 |

以上运行时参数会写回集成选项，重启后保留；结构性参数（实体指向、钳位边界）修改后会自动重载。

## 推荐上线路径

1. 安装后先开启「试运行模式」，观察 `status`/`reference`/`offset` 一两天；
2. 确认前馈与微调方向正确后，关闭试运行；
3. 若收敛太慢，调大步长（1.0）或缩短间隔（2 分钟）；若来回摆动，加大死区或拉长间隔。

## 开发

```bash
# 单元测试（控制环纯 Python，无需 HA 环境）
python3 -m pip install -r requirements_test.txt
python3 -m pytest tests/ -v

# 同步到 HA 的快速迭代（按你的 SSH 入口调整）
rsync -av custom_components/follow_me_climate/ <ha-vm>:/config/custom_components/follow_me_climate/
```

控制逻辑在 `custom_components/follow_me_climate/controller.py`，与 HA 完全解耦（适配器 + 传感器读取器 + 时钟注入），可直接单测。
